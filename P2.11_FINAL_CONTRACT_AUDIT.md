# P2.11 FINAL CONTRACT AUDIT

Second audit after implementation, against the reconciled contract. Sources:
working-tree diff (14 files, +916/−10, plus `test/p2-presentation.test.ts`),
focused suites (48 + 50 + batches above), full watchdog run (4218/23/8),
`tsc` (28 = baseline set), targeted biome (0 new diagnostics).

## Is P2.11 architecture still consistent with the reconciled contract?

Yes. Every reconciled element is implemented without revising frozen semantics:
verification display is observation-only (`noteVerificationObserved` →
`verification.observed` → attach-only reducer case); provenance lives in
projection/view/machine metadata (`projectProvenance`, watershed stamping,
envelope passthrough) and never on canonical rows; live and replay share one
reducer and one vocabulary; identity stays `(session_id, event_seq)` with
canonical comparison; child merge requires explicit linkage; TUI/ACP consume
snapshots/events only.

## Did implementation introduce any second authority?

No. Forensic import/usage scan of the display surface
(`src/presentation/**`, `src/ui/**`, `cli/commands/acp.ts`,
`cli/commands/exec.ts`): no `saveSession`/`appendHistoryEvent`, no run
lifecycle writers, no `VerificationRecord` writers, no `history_projections`
or `ContextView` references, no `CREATE/INSERT/sqlite/Database`, no
`session/journal|verification|persistence` imports in `src/ui`. The single
writer of durable observation remains `appendPresentationEvents`; its return
type widened to stats without changing write semantics. Guard-enforced
(`p2-architecture-guards`: messages, runs, verification-mutation, second
persistence).

## Can reconstructed state be mistaken for observed state?

No, by construction plus tests. `interrupted`/`parent-ended`/orphan
placeholders can only arise from rebuild inference or orphan evidence paths;
`projectProvenance` marks exactly those rows `reconstructed` at/below the
replay watershed; renderers show `[reconstructed]`/`[replay]` only when the
field is present; the live bridge (`toPresentationEvent`, guard-sliced) never
sets provenance. B3/B4/D5 plus transcript/simple marker tests pin the
behavior; A6/H1 pin absence-means-unmarked.

## Can UNKNOWN become success?

No. Three independent layers agree: (1) projection emits no marker without an
explicit verification object (`verificationMark(undefined) === ""`, tested);
(2) renderers gate the success marker on `verdict === "present"` (guard +
transcript/simple tests; `absent`/`inconclusive` render `[unverified:<v>]`);
(3) ACP/machine omit the verification key entirely when absent (F3, envelope
payload test). A terminal row without verification is byte-identical to its
pre-P2.11 rendering.

## Can identity collision overwrite durable observation?

No. Same identity + identical canonical payload → counted duplicate, skipped.
Same identity + different payload → counted collision, existing row preserved,
incoming rejected, one stderr diagnostic, no UPDATE anywhere in the path
(guard asserts `UPDATE presentation_events` absent). Proven by C3 (existing
`durationMs: 5` survives five colliding retransmissions) and C5 (storm).
Canonical comparison is key-order insensitive (C2: shuffled keys still dedupe).

## Can child context leak through presentation?

No. `finalText` is absent from projection, reducer verification path, both
renderers, ACP, exec, and setup display code (guard-enforced; adapter's only
uses remain the pre-existing turn→conversation path). Child rows stay
namespaced (`sub:tool` keys, E1–E4/E9); ambiguous parallels stay orphan (E5);
child verification merges only into child keys (E8); ACP preserves linkage
without narrative content (F1).

## Did any P2.12 work enter P2.11?

No. Guard scans the P2.11 surface for `Desktop|desktop|P2.12|long-running|
websocket`: zero hits. No reconnect-replay log, no durable UI chrome, no
retained-mode engine, no modal/input rewrite, no global event ID. Desktop
remains a future consumer of the same projection contract.

## Was vendor/minicore modified?

No. `git status --short vendor/` empty (guard test runs it); no `#minicore`
contract changes; kernel event vocabulary untouched (new `verification.observed`
is a presentation-layer member only).
