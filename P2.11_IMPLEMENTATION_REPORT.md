## 2. Architecture changes

Additive only, no frozen invariant revised:
- One new DomainEvent member observed through the existing adapter → queue →
  SQLite → reducer → snapshot → policy → consumer chain. No new pipeline.
- Provenance as view/machine metadata, never on canonical rows.
- Identity stays `(session_id, event_seq)`; comparison becomes canonical instead
  of `INSERT OR IGNORE`-blind.
- No changes to messages/runs/journal/verification/epoch/cursor/TaskGraph/
  Context/history-projections/CLI semantics/vendor.

## 3. Verification presentation wiring

`journal (canonical evidence) → setup emitter (fire-and-forget read) →
adapter.noteVerificationObserved → DomainEvent → reducer attach →
snapshot/policy/machine/ACP → TUI/linear renderers.`

- Emitted only with an explicit journal VerificationRecord for an exactly-one
  matched invocation; zero/multiple candidates → silence (UNKNOWN by derivation).
- Turn-level sweep covers same-turn late verification.
- Forwarded child completions resolve against the child journal and emit with
  the child session override, merging into child-namespaced rows.
- `recordExternalVerification` remains the only writer path; presentation never
  writes verification (guard-enforced).

## 4. Provenance implementation

`projectProvenance(entry, eventSeq, replayedUpToSeq)`: null watershed or
above-watershed → omit (live, documented default); at/below watershed →
`replay`, except `interrupted`/incomplete rows → `reconstructed`. Stamped on
snapshot activities/turns and machine envelopes; never on live bridge events
(verified by guard slicing `toPresentationEvent`). Renderers show `[replay]` /
`[reconstructed]` / `[verified]` / `[unverified:<verdict>]` (ASCII-safe) only
when fields are present; absence renders nothing and claims nothing.

## 5. Collision handling

`canonicalizePresentationPayload` (recursive sorted-key JSON) compares incoming
vs stored payload inside the write txn: identical → `{duplicates++}`, silent
idempotent skip; different → `{collisions++}`, existing row preserved, incoming
rejected, one stderr diagnostic, no runtime inference, no overwrite (UPDATE is
absent by guard). Return type widened to `PresentationPersistStats`; both
production callers map to void. Corrupt rows remain a load-path concern
(rejected + counted, valid state preserved).

## 6. Child presentation

Adapter pairing (`resolveChildLink`, exact-one else orphan) unchanged. ACP now
preserves `parentToolCallId` on `tool.*` (was finding-only). Child verification
attaches to child-namespaced activities via session override; parent ledger
never receives child rows (transcript/simple skip parent-linked rows).
`finalText` appears nowhere in the display surface (guard-enforced; adapter's
only uses remain the pre-existing turn→conversation path).

## 7. TUI changes

No engine rewrite: same snapshot/policy/call flow. Added per-invocation
deduped verification ledger lines, inline verification/provenance markers
(gated on field presence), and `clear()` resets. Existing rows render
byte-identically (268-test TUI/CLI batch green).

## 8. ACP changes

Projector-only: child linkage preserved, `verification.observed` branch,
provenance passthrough. Stream stays ephemeral, lossy, sanitized, capped;
no persistence, no replay log, runs stay independent.

## 9. Security/redaction

No new secret system. Verification events carry only invocationId (app key),
enum verdict/method, and timestamp — `evidenceReference` never leaves the
journal (guard: no `evidenceReference` outside session/verification). Machine
and ACP paths reuse existing scrub/cap/sanitize; all new markers ASCII-safe.
`cli/index.ts` change is type-level only.
