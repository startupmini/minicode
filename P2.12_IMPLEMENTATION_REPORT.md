## 2. Architecture changes

Additive only; no frozen invariant revised:
- Daemon = host only. It never becomes a writer, a second event system, or an
  authority for approval outcomes; identity stays `(session_id, event_seq)`.
- Session ≠ Thread ≠ Run are preserved: a hosted session is the same durable
  session object, merely living inside the daemon process.
- Consumer ≠ writer: consumers hold read/subscribe/approve/control scopes and
  offsets; the writer epoch fence still decides who may append.
- Storage failure → deny (never optimistic success); telemetry is counters
  only and is never read back as authority.
- Vendor untouched; `#minicore` contract unchanged.

## 3. Host & lifecycle

`minicode daemon start` (blocking) binds a loopback listener, writes
`.minicode/daemon-endpoint.json` (0600) holding host/port/incarnation/lease
plus the bootstrap trust root, optionally hosts sessions supplied by
`--prompt`/`--session`, and prints exactly one line per stream
(listening/endpoint/capability). Shutdown is strictly ordered —
mark-closing → halt-consumers → … → endpoint cleanup — so approvals never
hang unanswered, leases cannot masquerade as a live daemon, and children are
never reported complete without a report. The ordered sequence is pinned by a
guard that asserts the exact `#track` order and that shutdown covers every
step.

## 4. Protocol, handshake, subscription

Handshake order is `auth → frontiers → snapshot → cursor → replay →
replay_done → tail_marker → LIVE`. Snapshot is deliberately non-atomic (the
contract forbids presenting a frozen cursor as a consistent point-in-time);
replay is read from durable storage, so the offsets a consumer observes are
the store's, not the connection's. Subscription semantics: `"tail"` joins live,
`"resume"` continues from the stored offset, an explicit number replays from
that sequence (`0` = from the beginning). Offsets are monotonic; acks never
jump past the cursor; the per-connection queue is bounded
(`MAX_QUEUE_PER_CONN = 512`) with refusals when full instead of silent drops.

## 5. Durable approvals & consumer offsets

`daemon_approvals` records the machine
`requested → pending → {accepted|denied|expired|cancelled}|UNKNOWN`; terminal
states are never reversible, and a row still `pending` after a restart becomes
`UNKNOWN` rather than being guessed. Write failure or expiry is reported as
deny, never as fabricated success. `consumer_offsets` is the only source for
resume positions and is workspace-local.

## 6. Control API

Eight operations (`daemon.status`, `daemon.shutdown`, `session.list`,
`session.status`, `approval.list`, `approval.decide`, …), each with an
explicit minimum scope asserted by a guard. Idempotency: same key + same
payload → original outcome with `replayed:true`; same key + different payload
→ `IDEMPOTENT_REPLAY` refusal; failures are never cached. `daemon.shutdown`
defers its execution one event-loop turn so the `control_result` frame is
written before connections are torn down (found by CLI smoke: without this the
operator saw "socket tertutup" for a command that had actually succeeded).

## 7. Child supervision

`children.ts` supervises child processes of hosted sessions: no child is ever
adopted from another generation (guard asserts the literal `adopt(` is
absent), completion requires a report from that child, and children never
inherit approval authority.

## 8. Discovery, resource, telemetry

Discovery separates recency from liveness: an endpoint file with a fresh lease
is only a candidate, and only a successful probe reports `alive`. PID and
lease age are never decision inputs (guard). `resource.ts` does
edge-triggered monitoring; `telemetry.ts` counts events and is excluded from
every decision file by guard.

## 9. CLI surface

`minicode daemon <start|status|stop|issue|sessions|help>` — plain-stdout human
output, JSON via `--json`, one write per stream (writer inventory 6, owner
`human-cmd`). Exit codes: help 0, status alive 0 / not alive 3, unknown
subcommand 2, control failure 1. Three CLI bugs were found and fixed during
verification: (a) `cli/index.ts` ignores `dispatch()`'s return value, so
`daemon help` fell through into normal session creation until the handler
exited explicitly; (b) `hasFlag` stops at the first positional token, so
`--json` was never seen in a subcommand handler (repo convention:
`args.includes`); (c) a path value (`daemon --cwd D:\x`) was parsed as a
subcommand name — `firstPositional` now skips value-flag values, and `mulai`
is accepted as the alias the help text promises.

## 10. Security & sanitization

- No writer token, bootstrap secret, or session key ever crosses IPC
  (guard: `protocol.ts` credential-free).
- Endpoint file holds the bootstrap trust root only; `admin` scope does not
  imply the other scopes.
- All label/input paths sanitize at the IPC and composition entry points
  (daemon's own `sanitize.ts`), including refusal messages echoed to
  consumers.
- `src/daemon` contains no `console.*`; host diagnostics go through one warn
  channel (guard asserts exactly one `process.std*.write` in `host.ts`).
- Model/provider/label text from the network is untrusted input and is
  sanitized before display, per AGENTS.md.

## 13. Remaining known limitations

- Cross-process Desktop consumption is proven at the protocol/control level
  (separate OS processes for status/issue/sessions/stop plus in-process
  consumer tests over real loopback); there is no interactive Desktop UI
  screen in this milestone — the client library and CLI are the consumers.
- Handshake snapshot is intentionally non-atomic; consumers must treat
  `replay_done` + `tail_marker` as the LIVE boundary (contract requirement).
- Approval expiry depends on the broker's clock skew window; a restart while
  `pending` yields `UNKNOWN`, never an inferred decision.
- Coverage and pack gates stay red on the qualified baseline/flake set, as in
  P2.10/P2.11; neither gate is evaluated against P2.12 code specifically.
- `daemon start` prints a capability line to stdout; operators should treat
  that line as a bearer secret for the session (it is scoped and TTL-bound,
  but it is printed).
