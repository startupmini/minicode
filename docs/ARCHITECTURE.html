02 Alur eksekusi satu prompt #

Tujuh tahap jalur utama, lengkap dengan file tempat tiap tahap hidup. Subcommand admin dan mode MCP server tidak lewat alur ini.

1
Entry & parsing cli/index.ts → cli/args.ts → cli/router.ts argv dipisah jadi flag & prompt; dispatch ke subcommand (acp/auth/config/daemon/exec/mcp/memory/pricing/providers/sessions/skills/stats/doctor, plus alias models/sync) atau TUI. Flag tak dikenal tidak error — ia jadi kata prompt (§8).
2
Perakitan sesi cli/setup.ts → src/app/session.ts → src/app/{provider,tool,rag}-layer.ts Config dimuat; presentation event durable dimuat/rebuild; session kernel dibuat; provider + tools + permission dirakit; checkpoint, semantic event sink, dan callback UI (ask, wizard) di-inject — titik komposisi seluruh aplikasi.
3
Loop agen vendor/minicore/src/core/{session,loop}.ts session.run menjalankan executeTurn berulang (maxSteps default 50) di atas salinan ContextStore transaksional per turn — bisa di-rollback oleh checkpoint.
4
Streaming provider src/providers/router.ts → anthropic.ts · vendor openai-compat.ts Model dipilih, request dikirim, token di-stream sebagai event bus kernel → diterima presentation sebagai UiEvent.
5
Eksekusi tool vendor core/executor.ts → src/policy/executor.ts → src/tools/* Rantai gerbang §5: jail → permission → bash-guard → validateArgs → execute → truncation. Tool MCP eksternal dirutekan lewat src/mcp/client.ts (“serverid.toolname”).
6
Rendering output src/ui/render/{sanitize,markdown,markdown-table,table-grid,highlight,wrap,width}.ts → src/ui/assistant/simple.ts Teks tak terpercaya disanitasi, didekorasi markdown, diukur dalam kolom, lalu mengalir append-only ke scrollback. Assistant hanya mengonsumsi event UiBus.
7
Persistensi src/session/{persistence,shadow-git,checkpoint}.ts · src/telemetry/trace.ts Pesan dan semantic event durable disimpan inkremental ke sqlite (WAL, TTL 30 hari); tree per turn dicatat shadow-git di refs/minicode/*; trace jsonl untuk diagnostik & biaya. Tabel messages kini menyimpan reasoning + is_error (field kernel yang sebelumnya hilang saat resume) dan keduanya ikut prefix comparison agar append incremental tidak melewatkannya.

Sebaliknya, visibilitas tool hanya membatasi daftar yang dilihat model, BUKAN gerbang keamanan: tool yang disembunyikan masih mungkin dipanggil bila namanya ditebak, dan yang menolak tetap ceiling WorkMode. Visibility = irisan filter permission mode ∧ filter WorkMode (WorkMode tak pernah memperluas); tool MCP runtime ikut dibatasi. EXECUTE = default (tanpa ceiling tambahan, perilaku lama). Transisi WorkMode saat runtime (command /work-mode) berlaku pada sesi yang sedang berjalan: ceiling dievaluasi per pemanggilan tool, daftar tool yang dilihat kernel ikut berubah, hooks dievaluasi terhadap WorkMode aktif, dan delegasi berikutnya mewarisi WorkMode parent aktif. WorkMode tak bisa dinaikkan otomatis oleh model, anak, atau argumen delegasi. Catatan gate hooks: `shouldRunHooks(permissionMode, liveWorkMode)` dievaluasi per pemanggilan — sisi WorkMode dibaca LIVE, sisi permission mode memakai nilai startup sesi (semantik lama; `Tab`/`Shift+Tab` menggeser mode izin di dalam handler, bukan nilai gate hooks). Catatan scope state: WorkMode parent hidup di state modul proses (pola yang sama dengan `parentRouting`/`parentRunId` milik sub-agen). Entry point produksi yang saat ini didukung membangun SATU parent session per proses (index / exec / acp / daemon; autonomous child memanggil `createMinicodeSession` langsung dengan policy 6S terinjeksi + tool read-only, jadi tak mewarisi maupun menimpa WorkMode parent), sehingga pada jalur CLI produksi tak ada dua parent aktif yang saling menimpa WorkMode. Batas yang jujur: jaminan ini berasal dari topologi entry point, BUKAN dari invariant runtime — embedder atau pemakaian yang membuat beberapa parent session dalam satu proses belum punya jaminan isolasi per-session; bila dua parent dengan WorkMode berbeda saling menimpa, child dapat membaca WorkMode parent yang salah. Perbaikan menyeluruh butuh dependency injection atau state yang di-scope per-session, dan berada di luar scope P12 S2.2 ini.

08 Invarian struktural #

Aturan tak tertulis yang kalau dilanggar menghasilkan bug yang sudah pernah terjadi di repo ini.

  • Bun-only, zero runtime deps. bin menunjuk langsung cli/index.ts; tidak ada build step. dependencies package.json kosong dan harus tetap kosong.
  • Kernel beku. vendor/minicore hanya berubah lewat seam aditif + bun run vendor:minicore; aplikasi tidak pernah menulis ke dalam vendor.
  • Batas lapisan itu kode, bukan harapan. Matriks §1 dieksekusi sebagai test (test/ui-boundary.test.ts) — tambah modul baru berarti periksa ulang arahnya.
  • Teks tak terpercaya → sanitizeAnsi. Output model, hasil tool, dan isi berkas wajib disanitasi sebelum render; tanpa itu model bisa membersihkan layar atau keluar alternate screen.
  • Lebar diukur dalam kolom. Pakai displayWidth/truncateToWidth/padToWidth (src/ui/render/width.ts), bukan .length/.slice() — CJK & emoji 2 kolom.
  • c & glyphs adalah getter di src/ui/render/theme.ts yang membaca state runtime (dukungan UTF-8, NO_COLOR; palet tunggal sejak fitur tema dihapus). Menyimpannya ke const module scope membekukan nilai saat import — jebakan yang sudah tiga kali terulang.
  • Flag tak dikenal = kata prompt. cli/args.ts hanya mengenali whitelist flag; --typo tidak error tetapi ikut masuk teks prompt (args.ts:59-67, flagNameOf()). Tambah flag baru = daftarkan di whitelist.
  • Jail mendahului segala mode. Tidak ada jalur eksekusi tool yang boleh mem-bypass src/policy/jail.ts, termasuk allow-all dan tool MCP.
  • Tool tidak mengimpor lapisan app/sesi. Kebutuhan lintas-lapisan (mis. sesi sub-agen untuk delegate_task) disuntikkan dari composition root via setter DI; tanpa injeksi tool fail-closed. Arah providers → config juga satu arah sejak provisioning dipisah ke providers/provision.ts.
  • Satu tampilan: TUI fullscreen. Transkrip ala shell + status bar + popup komposit (/model, /provider, /sessions) di atas transkrip yang tetap terlihat (redup). Alternate screen HANYA lewat src/ui/runtime/screen.ts (enter/exit berpasangan + paintRegion tanpa clear); non-TTY/one-shot/layar kecil = tolak bersuara + batal. Tool call compact (satu baris › nama target). Dropdown / berbingkai dan terhapus di semua jalur keluar. REPL linier, footer lengket, overlay inline, jendela info: DIHAPUS.
  • Kontrak terminal TUI. docs/TERMINAL_CONTRACT.md (v7.4 TUI fullscreen 2026-10-20) membekukan klasifikasi writer, contract stdout/stderr, komposit popup, dan 35 invariant terminal (I1–I35) — wajib dibaca sebelum menyentuh output/rendering; setiap perubahan perilaku wajib update dokumen + test peta proteksinya.
  • Satu arbitrase transient + satu lifecycle modal. Semua painter stderr (garis turn, wizard spinner) lewat acquireTransientPaint/paintWrite di src/ui/runtime/statusline.ts; tulis asing non-UI saat painter aktif dikomit sebagai baris permanen — tidak hilang, tidak merusak transient. Semua modal lewat openAltScreen/close di src/ui/runtime/screen.ts; layar interaktif apa pun (popup/alt-screen/raw prompt) menahan painter transient via beginInteractiveScreen — spinner setup tak pernah menimpa prompt wizard.
  • Non-TTY = polos. Pipe/redirect/CI tidak boleh mengandung cursor control, animasi, atau warna (warna digate stdout.isTTY; NO_COLOR menang).
  • Peta ini harus hidup. Setiap perubahan struktur (tambah/hapus/pindah modul atau lapisan) WAJIB memperbarui docs/ARCHITECTURE.html dalam perubahan yang sama — lihat AGENTS.md.

09 UI/UX untuk developer — rendering terminal #

Ringkasan kontrak TUI fullscreen minicode: transkrip + status bar + popup komposit. Versi lengkap + residual risk yang disengaja ada di docs/TERMINAL_CONTRACT.md (v7.4 TUI fullscreen 2026-10-20); panduan pengguna di docs/USAGE.md.

1 · Prompt

minicode <mode> › — baris input interaktif + dropdown slash; satu-satunya elemen “hidup” saat idle.

2 · Pesan model

Streaming ke stdout, di-sanitasi, dibungkus per baris mengikuti kolom terminal; fence markdown indent 2 spasi.

3 · Aktivitas

Status bar fullscreen memakai ✦ sebagai indikator proses; timer HH.MM.SS berada di sebelahnya, redup idle dan putih aktif. Reasoning memakai dots ... → .. → .. Prompt minicode › tampil saat boot/idle, hilang saat busy, dan kembali otomatis setelah turn selesai; satu baris kosong memisahkan composer dari footer. MINICODE_MOTION=0 membuat animasi statis tanpa menghilangkan feedback.

4 · Hasil tool

Ledger stderr, compact: › nama target satu baris (hijau; tanpa bocor isi file); error › nama: pesan (merah). Section besar default minimize (+ label); expanded/verbose menampilkan isi.

5 · Error

✗ pesan actionable — sekali per kegagalan via takePendingError(); tidak pernah dump JSON/stack ke user.

Stream contract

stdout = output program (teks model, receipt). stderr = progress/diagnostik. Non-TTY: 0 ANSI, 0 spinner, 0 cursor control.

Transient rendering memiliki satu ownership mechanism (src/ui/runtime/statusline.ts):

Ownership

Painter garis turn (turn) dipakai pada shell/linier; TUI fullscreen status-nya dimiliki TuiApp dan clock-nya berjalan independen dari event. Wizard spinner tetap lewat acquireTransientPaint(kind).

Foreign writers

Diagnostik non-UI (router/providers/tool warnings) boleh menulis mentah ke stderr — arbitrator mengkomitnya sebagai baris permanen saat painter aktif.

Lifecycle tertutup

Status TUI memakai dots untuk reasoning dan sparkle untuk proses; timer berjalan dalam format HH.MM.SS dengan state warna. Cleanup terjadi pada sukses, kegagalan, pembatalan, serta double-abort.

Mutual exclusion

Painter vs spinner secara desain disjoint; overlap memicu signal [transient-paint] … sekali per pasangan (bukan crash).
